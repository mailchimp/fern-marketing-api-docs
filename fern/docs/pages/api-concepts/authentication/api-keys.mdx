---
title: API keys
description: How Mailchimp API keys behave, including their scopes and 1-year lifetime, and where they can and cannot be used.
---

An [API key](https://mailchimp.com/help/about-api-keys/) authenticates requests
against the account it was created in. It's the right credential when your
application works with your own Mailchimp data. To create one, see
[Generate your API key](/marketing/build/get-started/generate-your-api-key).

## What a key grants

You select a key's scopes, such as `campaigns:read`, when you create the key.
They're the same scopes OAuth 2 apps use, and the
[API reference](/marketing/api) lists the scopes each endpoint requires.

A key can only do what both its scopes and the
[role](/marketing/api-concepts/authentication#user-access-and-revocation) of the
user who created it allow.

Select only the scopes your application needs. If a key leaks, its scopes limit
what someone else can do with it, so treat it the way you'd treat a password.

## Expiration

A key expires 1 year after it's created. Expiration limits how long a leaked key
stays useful. After a key expires, requests made with it fail with `401`, and
the key can't be renewed. Create a new key and switch your application to it
before the old one expires.

A key also stops working if you delete it, or if the user who created it is
removed from the account; see
[User access and revocation](/marketing/api-concepts/authentication#user-access-and-revocation).

## Where keys can't be used

Anyone who holds a key can use it, so two environments are ruled out:

- **Browsers.** Mailchimp does not support client-side calls to the Marketing
  API using CORS requests. A key in front-end code is readable by anyone who
  loads the page.
- **Mobile apps.** A key shipped inside a distributed binary can be extracted
  from it. For iOS and Android, use the
  [Mobile SDK](/marketing/build/start-developing/mobile-sdk), which is built
  against a mobile-focused subset of the API.

Both cases have the same shape: the credential ends up somewhere you don't
control. Keep keys on a server you own.
