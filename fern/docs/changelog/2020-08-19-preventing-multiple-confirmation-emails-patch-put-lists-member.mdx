---
title: Preventing multiple confirmation emails on PATCH or PUT to Lists/Member endpoint
tags: ["Marketing API"]
---

It was possible to force multiple confirmation emails to be sent to a member when using identical [PATCH](/marketing/api/lists/update-member) or [PUT](/marketing/api/lists/upsert-member) requests to the [Members resource](/marketing/api/lists/list-members). We’ve corrected this behavior by preventing the duplicate confirmation emails from being sent.

Before this change, multiple confirmation emails would be sent to a member’s inbox, which could potentially be used for abuse.
